Lesson 9

Evaluate Each Step

A tool call is not automatically progress. After each call, the runtime should record what the result means and whether another step is justified.

Progress

Lessons 1–8 are studied and learned. Lesson 8 separated choosing an action from executing it. Lesson 9 adds judgment after execution.

The New Boundary

decide → execute tool → evaluate result → decide again

The evaluator does not choose the next tool. It describes the current step. The decision helper uses runtime state to choose what happens next.

Small, Deterministic Shape

type StepEvaluation = {
  useful: boolean;
  reason: string;
  shouldContinue: boolean;
};

For now, result count is enough evidence:

  • results > 0 → useful
  • results = 0 with another tool → not useful, continue
  • results = 0 with no tool left → not useful, stop

What the Stream Shows

{ type: "tool_executed", toolName: "search_jobs", resultCount: 1 }
{ type: "step_evaluated",
  toolName: "search_jobs",
  evaluation: { useful: true, shouldContinue: false } }

This makes the runtime inspectable: consumers can see both the evidence and the runtime’s interpretation of it.
