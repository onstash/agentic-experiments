Lesson 11

Why Evals Matter

Evals turn "this agent seems better" into "this agent won on the cases we care about."

Where We Are

Lesson 9 taught the runtime to judge one step. Lesson 11 widens the lens: evals judge the whole agent across many cases.

What Evals Are For

Evals are repeatable tests for agent behavior. They answer a practical question: did a change make the agent better, worse, or merely different?

  • catch regressions before users do
  • compare prompt, tool, or ranking changes
  • measure quality on a fixed set of cases
  • make improvement decisions evidence-based

How Evals Help The Agent

change code
   ↓
run the same test set
   ↓
compare scores and failures
   ↓
keep the change or roll it back

This helps the agent because improvement stops being a guess. The runtime can evolve without silently breaking search quality, ranking quality, or answer quality.

Simple Mental Model

Runtime step evaluation

Looks at one action inside one run and asks whether the step was useful.

Offline evals

Looks at many fixed examples and asks whether the whole system is improving over time.

What To Remember

  • step evaluation helps the loop decide what to do next
  • evals help the team decide what to ship next
  • both are feedback, but they operate at different scales
