Lesson 3 · about 20 minutes

Persist state in Pi’s session

Win: recent run profiles survive /reload, session resume, and branch navigation without a separate database.

Use the session as the source of truth

An in-memory array is only a cache. Pi already owns a durable, branch-aware session log, so the extension records each completed run there:

const ENTRY_TYPE = "turn-profiler-run"

pi.appendEntry(ENTRY_TYPE, run)

A custom entry is durable but does not enter the model’s context. This is the right fit for extension metadata that the UI needs but the LLM does not. See the official appendEntry() reference.

Persistence has two halves

write:   completed run → appendEntry()
read:    session_start → getBranch() → rebuild history

Saving without rebuilding leaves reload broken. Rebuilding without saving leaves nothing to recover.

Why read the branch?

getBranch() returns only entries on the active path through the session tree. If you fork from an earlier point, profiles from the abandoned future must not appear in the fork.

getBranch()
  → keep our custom entry type
  → take the latest five
  → reverse to newest-first
  → replace the in-memory cache

Two restoration events

  • session_start restores after startup, reload, resume, new session, or fork.
  • session_tree restores when navigation changes the active branch.

Both call the same restoration function. One state transition should have one implementation.

Retrieval check

Why is appendEntry() alone insufficient for persistence?

It writes durable data, but a new extension instance must still read the active session branch and rebuild its in-memory state.

Make one change

Temporarily remove the session_start handler, reload, and run /profile. Observe the empty cache. Restore the handler and reload again; the saved rows return.

This is a controlled failure: it proves that durable storage and state reconstruction solve different halves of the problem.

What we deliberately skipped

No JSON file and no database. Session entries already follow Pi’s resume, fork, and tree behavior. External storage would require us to recreate those semantics.
