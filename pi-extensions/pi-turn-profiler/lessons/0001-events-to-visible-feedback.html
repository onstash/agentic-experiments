Lesson 1 · about 15 minutes

Turn events into visible feedback

Win: by the end, Pi shows the latest agent-run duration and tool count in its footer.

The only model you need today

A Pi extension is a TypeScript factory. Pi calls it once and gives it an ExtensionAPI. Your factory registers reactions to future events.

export default function extension(pi) {
  pi.on("something_happened", (_event, ctx) => {
    ctx.ui.setStatus("my-id", "visible feedback")
  })
}

That is inversion of control: your code does not run the agent. It tells Pi what to call later. The official extension documentation defines the lifecycle and should be your primary reference.

Trace the flow

Open src/index.ts. Find these three transitions:

agent_start
  └─ reset clock and counter

tool_execution_end
  └─ increment counter

agent_settled
  └─ calculate duration and show final status

agent_settled is intentional. Unlike agent_end, it runs only after automatic retries, compaction retries, and queued continuation have stopped.

Retrieval check

Without reopening the source: which event should reset the timer, and which event should finalize it?

agent_start resets it; agent_settled finalizes it.

Make one change

Change the completed footer text from turn: to last:. In the running Pi session, execute /reload, then run another prompt. This proves you can edit and hot-reload an extension.
