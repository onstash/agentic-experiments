Lesson 2 · about 15 minutes

Keep history without keeping everything

Win: /profile shows the five most recent completed agent runs, newest first.

Build on your event model

Lesson 1 mapped events to changing state. This lesson changes the state shape: instead of overwriting one duration, each settled run becomes an immutable snapshot.

type RunProfile = {
  durationMs: number
  toolCount: number
}

const history: RunProfile[] = []

The snapshot matters. A run must keep the tool count it had when it finished; it must not read the mutable counter after a later run resets it.

The bounded-history algorithm

history.unshift(run)
history.length = Math.min(history.length, HISTORY_LIMIT)

unshift puts the newest result first. The next line truncates the array to five records. The data is tiny, so a plain array is clearer than a queue class or storage dependency.

Trace the data

Open src/index.ts and follow one run:

mutable working state
  startedAt + toolCount
          ↓ agent_settled
immutable snapshot
  { durationMs, toolCount }
          ↓ unshift + truncate
bounded history
          ↓ /profile
formatted notification
Retrieval check

Why does each history item store its own toolCount instead of reading the outer toolCount when /profile runs?

The outer counter changes on every run. A snapshot preserves the value that belonged to that completed run.

Make one change

Change HISTORY_LIMIT from 5 to 3. Reload, complete four runs, and confirm that /profile lists only three.

Then reload once more. The history disappears. That is not a bug yet: the array lives only inside this loaded extension instance. Lesson 3 will make it survive reloads and resumed sessions.
