Quick reference

Pi extension anatomy

The loop: register once → observe events → update state → render feedback.

Factory

export default function extension(pi: ExtensionAPI) {
  // Register events, tools, and commands here.
}

Choose the smallest API

  • pi.on(name, handler) — observe or alter lifecycle behavior
  • pi.registerCommand() — user-triggered slash command
  • pi.registerTool() — model-callable capability
  • ctx.ui.setStatus() — compact footer state
  • ctx.ui.custom() — interactive TUI; use only when simpler UI cannot work

Events used by turn-profiler

  • agent_start — reset the clock and counters
  • tool_execution_end — count one completed tool execution
  • agent_settled — finalize after retries and queued continuation stop

Rules worth remembering

  • Start long-lived resources at session_start, not extension load.
  • Clean resources at session_shutdown.
  • Guard TUI-only UI with ctx.mode === "tui".
  • Use pi.appendEntry() when state must survive reload or resume.
  • Prefer built-in TUI components before writing a custom component.
